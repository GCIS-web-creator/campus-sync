# CampusSync チャット監査ログ運用案

> 状態: **運用開始前の案**。学校の管理責任者・個人情報保護担当者による確認と承認が必要です。この文書だけで法令・校内規程への適合を保証するものではありません。

## 1. 目的と対象

対象は、CampusSync のクラス・学年・全校チャットに関する安全確保、通報対応、障害調査、管理操作の説明責任です。利用目的を超えて生徒を評価・監視するための利用はしません。

記録対象:
- メッセージの投稿・編集・削除。投稿者の内部ユーザーID、学籍番号、表示名、クラス、対象範囲、日時、本文、添付ファイルのメタデータ
- 通報の受付、理由、補足、対象メッセージのスナップショット、対応状況の変更
- リアクションの追加・取り消し
- 管理者によるメッセージ削除、通報処理、監査ログ閲覧、ログ書き出し
- 移行時点で現存していたメッセージの初回スナップショット

移行前にすでに削除されていたメッセージや、移行前の編集履歴は復元できません。初回スナップショットは過去の全会話ログではなく、移行時点の状態です。

## 2. 保存先と権限

- Supabase の `chat_audit_logs` を監査イベントの正本とします。
- `.cslogson` は JSON ベースのエクスポート形式であり、正本の代替ではありません。
- 生徒・一般の認証済みユーザーには監査ログの読み書きを許可しません。
- サーバー側 API のみが管理操作を行います。Service Role キーはサーバー環境変数にだけ保存し、ブラウザー・GitHub・ログ出力に含めません。
- 管理者共通パスワードは操作した職員個人を識別できません。正式運用前に職員ごとの認証、権限分離、MFA の採用を検討します。
- 監査ログの通常操作での更新・削除を禁止しても、データベース所有者やプロジェクト管理権限を持つ人による改変まで完全に防ぐわけではありません。強い証拠性が必要な場合は別管理の保管先、署名または独立したハッシュ保管を追加します。

## 3. 閲覧と持ち出し

チャット本文や添付ファイルは個人情報を含み得るため、必要な職員だけが必要な範囲を閲覧します。添付ファイルの管理画面用リンクは短時間の署名付き URL とし、第三者に転送しません。

`.cslogson` の書き出し前には、対象期間と利用目的を確認します。書き出し履歴自体も監査ログに記録します。エクスポートファイルは暗号化された学校管理の保管先に置き、個人端末・公開リポジトリ・公開共有リンクには保存しません。

ファイル内の SHA-256 ハッシュチェーンは、エクスポート後のイベント列の変更検出を支援しますが、単独では作成者の真正性や、データベースに記録される前の改ざんがなかったことを証明しません。

## 4. 保存期間と削除

**保存期間は未確定です。** 学校の規程、利用目的、適用される法令・ガイドラインを確認し、承認された期間を運用開始前に決定してください。通常メッセージ、通報に関する記録、セキュリティ事故に関する記録で異なる期間を定める必要があるか検討します。

無期限保存を既定値にしません。保存期間経過後の削除、バックアップの失効、法的・校内調査に伴う保全停止、本人からの問い合わせへの対応手順を定めます。監査ログに本文・添付ファイルのパスが含まれるため、本文を削除してもログに情報が残る点を利用者向け説明で明示し、ログの保存期間・削除方法と整合させます。

## 5. インシデント対応

- 重大な通報・安全上の懸念は、定められた教職員・管理責任者へエスカレーションします。
- 調査のためにログを保全する場合は、保全理由、担当者、開始日時、解除条件を記録します。
- 誤操作、誤閲覧、ログ欠損、添付ファイルの漏えいが疑われる場合の報告先と対応手順を別途定めます。
- 監査ログ書き込みに失敗した場合、管理操作は原則として失敗扱いとし、ログがないまま操作だけが完了する状態を避けます。

## 6. データベース適用と受入確認

1. Supabase のバックアップ・復旧手順を確認します。
2. 既存の Phase 1〜4 SQL の適用状態を確認します。
3. `supabase/class-chat-phase5-audit.sql` を Supabase SQL Editor で実行します。
4. テスト用アカウントで、投稿・編集・削除・リアクション・通報・通報状態変更を実行し、監査ログに対応するイベントが一度ずつ残ることを確認します。
5. 管理者による削除と通報処理が、状態変更と監査イベントの両方を原子的に記録することを確認します。
6. `.cslogson` を期間指定で書き出し、管理画面の検証機能でハッシュチェーンが成功することを確認します。ファイルのイベント本文を変更したテストでは検証が失敗することを確認します。
7. 不正なパスワード、未認証ユーザー、通常ユーザーからの監査ログ参照・変更が拒否されることを確認します。
8. 学校側の責任者が、利用者向け説明、保存期間、閲覧者、保管先、問い合わせ窓口を承認してから運用を開始します。

## 7. エクスポートのオフライン検証

Node.js が入った信頼できる端末で、ダウンロード済みファイルの整合性を検証できます。

```sh
npm run verify:cslogson -- ./campus-sync-chat-logs-YYYY-MM-DD.cslogson
```

または、依存パッケージを使わずに直接実行します。

```sh
node scripts/verify-cslogson.mjs ./campus-sync-chat-logs-YYYY-MM-DD.cslogson
```

検証成功は、ファイル内のイベント件数と SHA-256 ハッシュ連鎖が整合することを意味します。記録の真正性、正しい利用目的での出力、エクスポート前のデータベースの完全性を証明するものではありません。検証に使うスクリプトは、検証対象のファイルと別の、信頼できる GitHub コミットまたは学校管理のコピーから取得してください。
