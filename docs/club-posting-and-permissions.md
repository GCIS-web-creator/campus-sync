# 部活・委員会タイムライン投稿の管理

## 実装概要

- Adminは管理画面の「部活・委員会投稿管理」から直接投稿し、投稿を削除できます。
- Adminは学籍番号を指定して投稿許可を与えたり解除したりできます。
- 許可済みアカウントは許可コードなしで投稿できます。
- 許可されていない生徒には、その生徒の学籍番号に紐づく8桁の一回限りコードを発行できます。
- コードは24時間で期限切れになり、使用済みコードは再利用できません。DBにはコードそのものではなく `CLUB_POST_CODE_PEPPER` を使ったHMAC-SHA-256を保存し、コード確認は10分間に最大5回までです。
- 投稿者は公開タイムライン用の表示名を入力・編集できます。メールアドレスや学籍番号だけの表示名は拒否されます。
- タイムラインはDBの `created_at` を使って日本時間の年月日・時刻を表示します。
- 投稿サンプルをUIから削除しました。SQL migrationは既知の3件の旧サンプル行のみ削除し、他の投稿は維持します。
- 投稿許可の解除時、対象者の未使用コードも無効化します。
- 投稿APIは学校メールで認証されたユーザーを再検証し、DBのRPCで許可またはコードの使用を原子的に確認します。クライアントから `club_notes` に直接INSERTする権限は剥奪します。

## 有効化手順

1. 初回プロフィール設定のSQLが未適用の場合は、先に [supabase/student-profile-setup.sql](../supabase/student-profile-setup.sql) を実行します。
2. Supabase Dashboard → SQL Editor で [supabase/club-posting-permissions.sql](../supabase/club-posting-permissions.sql) の全内容を実行します。
3. Vercel の Environment Variables に `CLUB_POST_CODE_PEPPER` を設定します。これは32文字以上のランダムな秘密値で、コードの生成・検証に同じ値を使います。コードが未使用でも、値を変えると既存のコードは無効になります。
4. SQLの成功を確認してから、サイトの新しいデプロイが完了していることを確認します。
5. Admin画面で「部活・委員会投稿管理」を開き、管理用パスワードを入力して「最新データを読み込む」を押します。
6. Adminからテスト投稿を1件作り、学生側のタイムラインに正しい名前と日時で表示されることを確認します。
7. テスト用の6桁学籍番号を使って投稿許可を付与し、本人のログインでコードなし投稿ができることを確認します。
8. 許可を解除し、コードなし投稿が拒否されることを確認します。
9. 同じアカウントに24時間有効の一回限りコードを発行し、1回目は投稿成功、2回目は拒否されることを確認します。
10. 別の学生アカウントやゲストでは、他人の投稿権限やコード一覧にアクセスできないことを確認します。

## データの取り扱い

投稿の表示名は本人が選択できますが、なりすましを完全に防ぐものではありません。Adminは投稿者の実アカウントを監査でき、必要時に投稿削除・権限解除・未使用コードの無効化ができます。投稿名は「公式に本人確認された氏名」と同義ではないため、正式な学校連絡に使う場合はAdminから投稿する運用を推奨します。

SQLを実行するまではAPI/UIだけ反映されていても投稿は正常動作しません。GitHubのコード更新、Vercelの成功、SupabaseのSQL実行、実アカウントの動作確認は、それぞれ別のチェックポイントです。
