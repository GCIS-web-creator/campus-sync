## Phase 0で確定した方針

1. 初期版はユーザー1人につき惑星1個。初期名は「わたしの惑星」、公開設定はOFF。
2. 学習XP・学校貢献XP・知識XPを別々に記録する。学習XPは有効な集中60秒につき1 XP、東京時間の日次上限は10,800秒（180分）。
3. 学校貢献XPはAdmin承認後に10 / 25 / 50 XP。知識XPは採点可能な問題の初回正解に通常2・応用4・発展6 XPを付与する。
4. 自然成長は保存済みPomodoroの東京時間日合計600秒（10分）以上を有効な学習日とし、1日につき自然成長値1。日次最大1、累積上限なし、衰退なし。Planetube・YouTubeは使わない。
5. 文明発展スコアは「学習XP + 学校貢献XP + 知識XP + 自然成長値×5」。Stage 0〜5のしきい値は0 / 100 / 500 / 1,200 / 2,500 / 5,000。
6. 技術・社会・研究・自然の4軸はそれぞれ独立したLevelを持つ。各軸のレベル条件はロードマップを正本とする。
7. XP・自然成長値を消費しない。段階・解放は後戻りせず、非公開を初期値とする。
8. PC・スマートフォンのワイヤーフレームを定義し、Planetube・既存Pomodoro・学校機能・認証・通知を非破壊で維持する。

数値は仮想テストケースで初期ペースを確認した基準値であり、本番利用データからの統計的な最終調整ではない。将来調整時はルールバージョンを上げ、過去台帳を改変しない。

## Phase 1 — 現在の初回実装状況

詳細な完成設計は [Phase 1 データベース設計書](./planet-civilization-phase1-database-design-ja.md) を参照する。現時点のDraft PRは初期プロトタイプであり、Phase 1完了ではない。

### 既に存在する初期プロトタイプ

Draft PRでは次の3テーブルと学習XP付与関数を追加している。

- `campus_planets`: 一人一惑星、惑星名、公開設定、文明段階。
- `campus_planet_growth`: 学習XP・学校貢献XP・知識XP・自然成長値の集計キャッシュ。
- `campus_xp_ledger`: XPの根拠となる追記型台帳。発生元とXP種別の一意制約で重複を防止。
- `campus_award_learning_xp`: 保存済み学習セッションから有効集中秒数を検証し、学習XPを付与するDB関数。

### セキュリティ・処理の初期実装

- 3テーブルともRLS有効。
- authenticatedには本人分のSELECTだけを許可し、クライアントから直接INSERT / UPDATE / DELETEできない設計。
- XP付与関数はservice_roleだけが実行できる。
- サーバーAPIでログインJWTを検証し、ログイン本人のuser_idと学習記録IDを使う。
- DB関数内で惑星行をロックし、同一ユーザーの日次XP上限を直列化して計算する。
- XP台帳への追加と成長キャッシュの更新は同一DB関数呼び出しのトランザクション内で行う。
- 同じ学習セッションIDで再付与されないことを一意制約と既存行確認で防ぐ。

## Phase 2 — Pomodoro連携の初回実装

- 既存 student_study_sessions を唯一の学習セッション記録として読み取る。既存の保存形式・RLS・タイマー処理は変更しない。
- 有効集中時間60秒につき1 XP。秒単位で同じ日の累積を管理し、端数は次のセッションへ繰り越す。
- 東京時間の1日あたり有効集中時間10,800秒（180分）をXP算定対象とする。
- 上限を超えても元の学習セッションは削除・短縮しない。
- 同じ学習セッションIDからのXP再付与は行わない。
- 総合文明段階の必要XPはStage 1=60、Stage 2=240、Stage 3=600、Stage 4=1200、Stage 5=2400。詳細はPhase 0設計書を正本とする。
