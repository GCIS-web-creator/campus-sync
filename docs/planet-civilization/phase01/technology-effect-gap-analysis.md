# 研究→地上視点の連携と効果ギャップ分析

- 調査日: 2026-11-28 / 対象: `0a66b36`

## 1. 結論

**研究の解放状態は、地上視点にも惑星視点にも一切伝わっていない。** 地上視点が受け取る文明側の値は `civilization_stage` だけで、その効果は超高層の高さに限られる。

## 2. 実際の経路

```
[研究]  PlanetTechnologyTree ──GET/POST──▶ /api/planet-technology-tree ──▶ campus_planet_technology_unlocks
                    │
                    └─ 画面内の state(purchasedIds)で終わる

[地上]  PlanetCivilization ──GET──▶ /api/planet-civilization ──▶ planet, growth, ledger, MP(研究情報なし)
          └ Planet3DPanel {stage, planetAssetId, mpBalance, onStartStarTravel}
                └ CityGroundView {planetId, planetName, atmosphereColor, stage, onBack}
```

- 研究ツリーと惑星パネルはタブで排他表示され、状態を共有する親stateやContextが無い。
- `campus_planet_technology_unlocks` を読むのは研究ツリーAPIだけ。`lib/planet-technology-tree` をimportするのは研究ツリーの画面とAPIだけ(検索で確認)。
- `campus_planet_unlocks`(building / technology / landscape)は読み書きするコードが無い。研究購入はこの表に書かない。
- `campus_planet_events` の `unlock` は記録のみで読み手が無い。
- 研究購入で `civilization_stage`・成長軸・スコアは変化しない。

## 3. 存在する連携・存在しない連携

| 入力 | 惑星視点 | 地上視点 | 研究ツリー |
|---|---|---|---|
| Stage | 夜の灯りの強さ | 超高層の高さ、表示文字 | ノードの公開条件 |
| 研究解放 | なし | なし | 次ノードの解放 |
| 4軸Level | なし | なし | なし |
| 各XP・自然成長値 | Stage経由のみ | Stage経由のみ | MP(自然成長値を除く) |
| `campus_planet_unlocks` | なし | なし | なし |

## 4. 設計書との差

| # | 設計書(roadmap) | 実装 | 影響 |
|---|---|---|---|
| G1 | 知識XPで研究・技術ツリーを解放 | 全XPから生まれるMPで購入 | 研究と知識の結びつきが無い |
| G2 | 各軸の条件で建物・景観・技術が自動解放(Phase 5) | 未実装。表のみ | 成長軸が見た目に出ない |
| G3 | Stage 0は文明施設がほぼない。段階で住居→都市→惑星文明 | Stage 0から超高密度の近未来都市 | Stageの視覚的意味が薄い(直近の要望による地上刷新の結果) |
| G4 | 自然成長で森林・海・生態系が発展 | 自然成長は見た目に未反映。緑は「昼」切替で全員同じ | 継続の成果が見えない |
| G5 | 活動比率で惑星の個性 | 差は番号と大気色のみ | 同上 |
| G6 | 学校貢献は社会・都市を発展 | 都市要素と未接続 | 同上 |
| G7 | 解放済みは失われない | 研究解放は永続(満たす) | — |

G3は、直近の「1視点・超高密度サイバーパンク都市」という要望と設計書が衝突する点。次Phaseで優先順位の決定が必要。

## 5. 効果未実装ノード

- 状態や見た目を変える効果: **1,314ノードすべて未実装**。
- 前提解放以外に何も無い末端: 技術Lv10の **130ノード**。
- 説明文は技術1,300件が定型で、個別効果の定義に使える情報は分野・テーマ・Lvだけ。

## 6. 連携に使える既存の土台

- `GET /api/planet-technology-tree` は `purchasedNodes`(node_id, branch_id, node_type, unlocked_at)を返す。読み取りはDB変更なしで可能。
- ノードIDから分野・テーマ・Lvが決まる。
- `buildCityLayout` は純関数で、入力追加とテストが容易。小物はグループ単位(shared / night / green)。
- 夜はdraw call、昼は三角形が既に多い(ground-view §8)。要素追加は性能予算が前提。
