## 先に決めること

| # | 決定事項 | 推奨 |
|---|---|---|
| D1 | 学習XP上限と技術Lvしきい値の正(3時間系 / 12時間系) | 本番定義を取得して正とし、マイグレーションと画面を一致させる |
| D2 | Stageと地上都市の関係(最初から超高密度か、段階的に育つか) | 高密度は保ち、Stage 0〜2は低層・灯り少なめ等で段階差を付ける |

| D6 | `VerdiaGroundView` と素材 | 使う予定が無ければ削除(別PR) |

## Phase 02: 正本の確定(アプリ挙動は変えない)

1. 本番DBを参照のみで確認(civilization-stage-spec §8のSQL)。
2. リポジトリに無い定義(`campus_recalculate_learning_xp` 等)をマイグレーションとして取り込む。適用はせず差分確認。権限(authenticatedが実行できる関数の本人限定)を点検。
3. 学習記録の自己申告値に対する不正対策の要否を判断(同 §7)。
4. D1〜D6を決定。

別件の小修正: 自由航行・星系旅行が021〜050の地表画像を読めない点(ground-view §7)。`getPlanetSurfaceTextureUrl` の利用で直せる。

完了条件: 本番とリポジトリの関数・しきい値の差分が0、または差分が文書化されている。

## Phase 03: 効果定義と状態解決(表示はまだ変えない)

1. バージョン付きの効果定義 `lib/planet-effects.ts`(分野・テーマLv → 効果パラメータ)。
2. 純関数 `resolveCityState({stage, purchasedNodeIds, growth})`。未知のノードIDは無視。
3. 単体テスト: 空・全解放・分野別・非後退。`test-planet-technology-tree` を `package.json` のbuildにも追加(現在はCIの個別手順のみ)。

DB変更なし(解放状態は既存表から導出)。

## Phase 04: 地上視点への配線と性能土台

1. 研究解放を `PlanetCivilization` で取得し、`Planet3DPanel` → `CityGroundView` へ渡す。研究購入後に再取得。
2. `buildCityLayout` / `makeCityProps` が状態を受け取る。取得失敗時は現行の見た目。
3. スマートフォンの地上視点の高さを拡大。反射テクスチャのリサイズ追従、品質段階(反射・ブルーム・葉の数)、看板と発光の命令削減、コンテキスト喪失対応。
4. 実機で計測。

完了条件(目標案): 中級スマートフォンで30fps以上、夜のdraw call 200以下、昼の三角形100万以下。

## Phase 05: 分野効果の実装(3回に分割)

- 05a: 建築・都市、交通・物流、エネルギー(既存要素の増減で表現可能)
- 05b: 農業・食料、水資源・衛生、環境・気候、素材・製造
- 05c: 通信・情報、計算・自動化、医療・生命科学、教育・科学、航空・宇宙、社会制度・文化

各回: 解放前後のスクリーンショット比較、性能予算の確認、研究画面に「地上で変わること」を表示。

## Phase 06: Stage・成長軸・惑星個性

Stage差の拡充(D2)、自然成長→緑量、社会→公共施設、惑星種別の環境データを50惑星分整備、必要なら `campus_planet_unlocks` への記録(追加のみのマイグレーション)。惑星視点の地表解像度(011–020は192×96)と未使用素材の反映は独立して実施可能。

## 全Phaseの非破壊条件

- Stage定義・しきい値・ノードID・コスト・前提を無断で変えない(購入済み行はIDで参照される)。
- 台帳は追記のみ。既存の解放・Stageを後退させない。
- 本番デプロイは依頼があった時だけ(`[deploy-worker]`)。DBマイグレーションは別途承認。
