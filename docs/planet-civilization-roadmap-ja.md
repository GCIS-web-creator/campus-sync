# CampusSync 惑星・文明システム ロードマップ

- 最終更新: 2026-11-21
- 対象: CampusSync 本体
- 状態: Phase 0 設計完了 / Phase 1 設計・実装の検討前
- 対象ブランチ: feature/planet-civilization-phase1-2-20261120

この文書は、CampusSync内に個人の惑星を持ち、CampusSync内で確認できる学習・学校への貢献・知識習得・継続的な活用に応じて、惑星の自然と文明が成長する仕組みを定義する。PlanetubeやYouTubeの利用履歴には依存しない。フェーズを順番に進め、既存機能を壊さず、小さく動作確認しながら拡張する。

---

## 1. プロジェクトの目的と基本原則

CampusSyncの中に、生徒一人ひとりが自分の惑星と文明を持てる成長システムを作る。

学習記録を単なる時間や数字で終わらせず、積み重ねが惑星の見た目・施設・技術・社会の発展として見えるようにする。

### 基本原則

1. **CampusSync内で完結させる。** XP、惑星、文明、成長値、建物、成長履歴はCampusSyncのSupabaseで管理する。
2. **Planetube本体は変更せず、成長データ源にも使わない。** PlanetubeのXP、惑星レベル、封印機能、ユーザーデータ、YouTube利用状況をこの機能から読み書きしない。
3. **既存のPlanetube統計画面を残す。** 現在のPlanetube画面は既存機能として維持し、新しい文明画面に置き換えない。
4. **最初は一人につき一つのメイン惑星。** 複数惑星の所有・惑星間移住などは初期版の対象外。
5. **努力・理解・貢献を別々に評価する。** 勉強時間だけで知識が増えたことにせず、学校への貢献も学習時間と混ぜない。
6. **記録を消さず、不正な重複付与を防ぐ。** XPの根拠となる履歴を保存し、同じ活動からXPを二重に付与しない。
7. **競争を強制しない。** 学習時間の公開ランキング、未ログインによる減点、惑星の衰退は作らない。
8. **シミュレーション管理ゲームにはしない。** 資源の採掘・消費、建物の手動配置、住民管理、課金・ガチャなどは初期版に含めず、成長に応じた外観変化を中心にする。
9. **公開は任意で、初期状態は非公開。** 初期版では本人だけが自分の惑星を閲覧できる。他人の惑星を見せる機能は後続フェーズで別途設計する。

## 2. XPと惑星成長の全体設計

このシステムでは、3種類のXPと1種類の自然成長値を使う。名前が似ていても、用途を明確に分ける。

| 種類 | 何を評価するか | 主な獲得源 | 惑星で成長するもの |
|---|---|---|---|
| **学習XP** (Learning XP) | 学習に取り組んだ時間・努力 | CampusSyncのポモドーロ集中記録 | 技術文明・科学施設・図書館・研究設備 |
| **学校貢献XP** (Contribution XP) | 学校や周囲への具体的な貢献 | 生徒の活動申請とAdmin承認 | 社会文明・住宅・道路・公共施設・文化 |
| **知識XP** (Knowledge XP) | 内容を理解し、正解などで知識を示した成果 | CampusSync内の採点可能な練習問題・小テスト | 研究・専門分野・技術の解放 |
| **自然成長値** (Nature Growth) | CampusSyncを継続的に活用した実績 | CampusSync内の確認済みアクティビティ | 森林・海・植物・生態系・自然景観 |

### 2.1 学習XP — 技術文明を発展させる

- 初期値は**有効な集中時間1分につき1 XP**。
- ポモドーロの集中時間だけを対象とし、休憩時間は加算しない。
- 一時停止中の時間は加算しない。
- 途中終了でも、保存された有効な集中時間は対象にする。
- 学習記録が保存された後、サーバー側で元の学習記録を検証して付与する。
- XPは消費する通貨ではなく、蓄積型の成長実績とする。
- **XP算定上限は東京時間の1日あたり180分（10,800秒）**とする。全セッションの有効集中秒数を日単位で合算し、60秒ごとに1 XPを付与する。端数秒は同じ日の次のセッションへ繰り越す。
- 上限を超えた分も元の学習記録にはすべて保存する。上限はXPだけに適用し、学習記録・学習時間・学習分析を削らない。
- XP上限は学習を制限するものではなく、放置タイマー等による過剰なXP増加を抑えるためのものとする。

タイマーは集中セッションの記録であり、実際に内容を理解していたことまで証明するものではない。そのため、時間から付与するのは学習XPだけとし、知識XPは別の方法で判定する。

### 2.2 学校貢献XP — 社会・都市を発展させる

対象例:

- 委員会・生徒会・係の活動
- 学校行事の準備・運営
- 部活動での運営・支援・学校への貢献
- 学校環境の改善や、学校全体に役立つ活動
- Adminが認めたその他の具体的な貢献

付与の流れ:

1. 生徒が活動内容・実施日・説明を申請する。
2. Adminが内容を確認する。
3. 承認された場合だけ学校貢献XPを付与する。
4. 承認者・理由・付与量・対象活動を履歴に残す。

単なる参加登録や自己申告だけでは付与しない。同じ活動の重複申請・重複承認を防ぐ。初期の付与量は、Adminが次の定型値から選ぶ。

| 区分 | 初期付与量 |
|---|---:|
| 小規模な貢献 | 10 XP |
| 通常の貢献 | 25 XP |
| 大きな貢献 | 50 XP |

自由入力による任意のXP量は初期版では許可しない。付与量の変更が必要になった場合は、ルールを更新した日以降の申請に適用し、過去の承認済み履歴を自動変更しない。

現在の既存貢献スコア・履歴は新しい文明XPと同一視しない。既存の貢献データはそのまま維持し、Phase 1で参照箇所・依存関係・RLSを調査してから必要な接続方法を決める。

### 2.3 知識XP — 研究・技術を解放する

知識XPは「勉強した時間」ではなく、**理解したことを確認できた成果**に付与する。

獲得対象:

- CampusSync内の採点可能な練習問題に初めて正解する。
- CampusSync内の採点可能な小テストで初めて正解する。
- Admin・先生が登録した知識確認問題に初めて正解する。

初期値:

- 通常難易度の問題の初回正解: **2 XP**
- 問題の難易度に応じた倍率: 通常1倍・応用2倍・発展3倍を初期基準とする。
- 同じユーザー・同じ問題の2回目以降の正解: 学習履歴には残すが、原則として追加XPなし。
- 正誤判定ができない課題・自由記述は、採点できる仕組みができるまで付与対象にしない。
- 単に問題や教材を開いただけでは付与しない。

知識XPは学習XPの代用品ではない。タイマーを長く動かすだけでは知識XPは増えない。

### 2.4 自然成長値 — CampusSyncの継続利用で自然環境を育てる

自然成長値はPlanetubeやYouTubeの利用状況ではなく、**CampusSync内で確認できる意味のある活動の継続**を表す。ブラウザ全体の利用時間や、他アプリの利用状況は取得しない。

自然成長値を獲得できる対象アクティビティ:

- 有効な集中時間が合計10分以上あるPomodoro学習記録の保存
- CampusSync内の対象問題での初回正解
- Adminが承認した学校貢献活動

獲得ルール:

- 対象アクティビティが一つ以上あった東京時間の暦日につき、自然成長値を**1**付与する。
- 同じ日に対象アクティビティが複数あっても、自然成長値は最大1。
- ログイン、画面を開いたままにすること、ページ更新、自動通信、単なる閲覧だけでは付与しない。
- 対象アクティビティの保存・承認をサーバー側で確認し、同じ日への重複付与を防ぐ。
- 連続利用を途切れさせても既に獲得した自然成長値は減らさない。未利用日による減点・惑星の衰退はない。

成長する要素:

- 草原・森林の拡大
- 海・水源の景観
- 植物や生物の種類
- 生態系の豊かさ
- 惑星の大気・自然環境の演出

**データ上の制約:** CampusSync内で確認できるアクティビティだけを使用する。Planetubeのセッション情報、YouTube閲覧履歴、URL履歴、検索履歴、他アプリの利用状況を取得・推測して自然成長値に変換しない。

### 2.5 惑星全体の文明段階と4つの成長軸

- 惑星全体の文明段階は、**学習XP + 学校貢献XP + 知識XP**の累計で決める。
- 自然成長値はXPに換算せず、自然環境の成長軸だけに反映する。
- XPは消費されず、累計値として残る。
- 4つの成長軸はそれぞれ独立して蓄積・表示する。

| 成長軸 | 対応する値 | 見た目・機能の変化 |
|---|---|---|
| 技術文明 | 学習XP | 研究所、図書館、発電施設、交通技術、科学施設 |
| 社会文明 | 学校貢献XP | 住宅、道路、公園、公共施設、街並み、文化施設 |
| 研究・知識 | 知識XP | 技術ツリー、研究テーマ、専門施設、研究成果 |
| 自然環境 | 自然成長値 | 森林、海、動植物、大気、自然景観 |

各成長軸のレベル・建物・景観の個別解放条件は、軸ごとの累計値を元に判定する。具体的なDB列・レベル算定式・解放管理の実装方法はPhase 1以降で設計する。初期版では、まずXP内訳・自然成長値・全体段階を正確に表示する。

## 3. 惑星・文明の構造

### 3.1 文明段階

惑星の発展は、少しずつ見た目が変わる全6段階にする。初期版の段階判定は総合XPの累計値を使い、段階は後戻りしない。

| Stage | 段階名 | 必要な総合XP | 見た目の変化 |
|---:|---|---:|---|
| 0 | 原始惑星 | 0 XP | 自然が中心。文明施設はほぼない |
| 1 | 集落時代 | 60 XP | 最初の住居・小さな集落の灯りが生まれる |
| 2 | 都市形成期 | 240 XP | 住宅街・道路・公共施設が増える |
| 3 | 産業・研究時代 | 600 XP | 研究施設・交通網・産業施設が発展する |
| 4 | 高度文明 | 1,200 XP | 大都市・先端研究施設・豊かな文化が共存する |
| 5 | 惑星文明 | 2,400 XP | 惑星全体に文明の光が広がる |

総合XPは学習XP・学校貢献XP・知識XPの合計とする。自然成長値はこの合計に含めず、自然環境の表現に反映する。段階のしきい値は初期基準値として固定し、変更する場合は仕様を更新してから適用する。

### 3.2 XPは消費させない

- XPを建物購入で消費する方式にはしない。
- 獲得したXPは累計値として残る。
- 条件を満たすと施設・景観・技術が自動的に解放される。
- 解放済みの建物や環境は、ログインしない期間があっても失われない。
- XPの配分ルールを変更しても、過去の努力を不利益にする再計算は行わない。誤付与の修正は監査可能な調整履歴を残す。

### 3.3 惑星の個性

- 初期版は全員が同じ基本タイプの惑星を一つ持つ。惑星タイプを選んだり、複数の惑星を所有したりする機能は設けない。
- 学習XP・学校貢献XP・知識XP・自然成長値の比率によって、同じ基本惑星でも外観の発展方向に個性が出る。
- 技術寄り: 研究施設や先端技術が発達した惑星
- 社会寄り: 都市・公共施設・文化が発展した惑星
- 研究寄り: 専門研究や知識施設が充実した惑星
- 自然寄り: 森林・海・生態系が豊かな惑星
- バランス型: 技術・社会・研究・自然が調和した惑星

特定の型が最強という仕組みにはしない。どの方向にも魅力や固有の建物・景観を用意する。初期の表示名は「わたしの惑星」とし、名前変更は初期リリース後の拡張候補とする。

## 4. 画面・操作の設計

### 4.1 既存画面との分離

CampusSync内に次の画面を分けて設ける。

- **Planetube:** 現在のPlanetube統計・封印セッション・実績を確認する既存画面。既存機能を維持する。
- **惑星・文明:** CampusSync独自のXP・惑星・文明・自然環境を確認する新しい画面。

惑星・文明画面はPlanetubeの統計画面を置き換えない。Planetubeの利用状況を惑星成長の判定に利用しない。

### 4.2 PC版の基本ワイヤーフレーム

1. **ヘッダー:** 「惑星・文明」、惑星名、現在の文明段階を表示する。
2. **メイン領域（左・約60%）:** 惑星の大きなビジュアルを表示する。文明段階・成長軸に応じて外観が変化する。
3. **成長サマリー（右・約40%）:** 総合XP、次の文明段階までの進捗、学習XP・学校貢献XP・知識XP・自然成長値を表示する。
4. **下部:** 技術・社会・研究・自然の成長軸、最近の成長履歴、次の段階で変化する要素を表示する。

### 4.3 スマートフォン版の基本ワイヤーフレーム

1. ヘッダーと文明段階
2. 惑星ビジュアル（横幅に合わせて縮小し、惑星全体が見える）
3. 総合XPと次段階への進捗
4. XP・自然成長値の内訳を2列カードで表示
5. 4つの成長軸と最近の履歴

横スクロールを必須にしない。主要な情報・更新・履歴確認は縦スクロールで完結させ、文字を小さくしすぎない。

### 4.4 初期版の操作範囲

- 自分の惑星を閲覧し、データを再読み込みできる。
- 成長段階・XP内訳・最近の付与履歴を確認できる。
- XP付与に失敗しても、元の学習記録は保持する。再試行しても二重付与されない。
- 建物配置、資源管理、住民操作、他人の惑星訪問、公開ランキング、共同ミッションは初期版に含めない。

## 5. 実装フェーズ

各フェーズは、完了条件を満たしてから次へ進む。複数フェーズを一度に実装して、データ不整合や原因不明の不具合を増やさない。

### Phase 0 — 仕様・画面設計の確定

**目的:** 実装前にXPの意味、獲得条件、初期数値、画面構成、公開範囲を確定する。

- [x] CampusSync独自機能として作る。
- [x] Planetube本体のデータ・機能を変更せず、惑星成長のデータ源にも使わない。
- [x] 学習XP・学校貢献XP・知識XP・自然成長値を分離する。
- [x] 学習XPの付与率を1分=1 XP、東京時間の日次上限を180分とする。
- [x] 学校貢献XPをAdmin承認後に10 / 25 / 50 XPの定型値で付与する。
- [x] 知識XPを対象問題の初回正解に限定し、通常2 XPを基準に難易度倍率を適用する。
- [x] 自然成長値をCampusSync内の確認済み活動日につき最大1とする。ログイン・放置・単なる閲覧は対象外。
- [x] 総合文明段階を学習XP・学校貢献XP・知識XPの合計で判定し、6段階の必要値を定義する。
- [x] 惑星は初期版で一人一つ、同じ基本タイプとする。
- [x] XPを消費せず、成長・解放を失わない方式にする。
- [x] 初期版は非公開・本人のみ閲覧とする。
- [x] PC・スマートフォンの画面配置と初期操作範囲を定義する。

**Phase 0 完了条件:** XPの種類・獲得条件・上限・文明段階・自然成長・公開範囲・初期画面構成が本書に明記され、初期実装の判断基準がそろっている。数値は初期基準値として固定し、実利用データを確認した上で、将来の変更は別途仕様更新として扱う。

### Phase 1 — データベースとXP台帳の基盤

**目的:** XPを安全に保存し、あとから正確に再計算できる仕組みを作る。

設計する主なテーブル:

| テーブル案 | 役割 |
|---|---|
| **campus_planets** | ユーザーごとの惑星名・公開設定・作成日時 |
| **campus_xp_ledger** | XPの付与履歴。種別・量・理由・発生元を保存 |
| **campus_planet_growth** | 技術・社会・研究・自然の成長値とレベル |
| **campus_planet_unlocks** | 解放済み建物・技術・景観 |
| **campus_planet_events** | 文明段階アップなどのイベント履歴 |

実装要件:

- XPの台帳を唯一の正本とし、累計値は台帳から再計算できるようにする。
- 同じ発生元ID・XP種別の二重付与をDB制約で防ぐ。
- XP付与はサーバー側の検証済み処理を通す。クライアントから自由にXPを書き込めないようにする。
- XP付与と惑星成長値の更新は、可能な限り一つのトランザクションで行う。
- 生徒は自分の惑星・自分の台帳だけを参照できるRLSにする。
- Admin権限は必要な承認・監査処理だけに限定する。
- 既存の貢献スコア・学習履歴テーブルを変更する場合は、先に依存箇所を調査する。

**完了条件:** 2つ以上のテストアカウントで、他人のXP・惑星を読み書きできない。重複登録・連続送信・再読み込みでもXPが二重に増えない。

### Phase 2 — ポモドーロと学習XPの連携

**目的:** 最初の実際に動くXP獲得経路を作る。

- CampusSyncの集中モードで保存した学習記録を対象にする。
- 有効な集中秒数から学習XPを計算する。
- 休憩秒数・一時停止時間は除外する。
- 途中終了した場合も、保存された有効な集中時間を対象にする。
- 学習記録ID単位でXP付与済みかを管理する。
- 付与したXPと根拠となる学習記録を確認できるようにする。
- XPの対象上限を設けても、通常の学習時間・履歴は削除しない。

**完了条件:** タイマーを開始・一時停止・再開・途中終了・完了した全パターンで、集中時間とXPが一致する。更新・再送信による二重付与が発生しない。

### Phase 3 — 学校貢献XPとAdmin承認

**目的:** 学校への貢献を適切に評価し、社会文明に反映する。

- 生徒が活動内容・実施日・説明を申請できる。
- Adminに承認待ち一覧を設ける。
- 承認・却下・差し戻しの状態を管理する。
- 承認時に定型XP量と理由を確定し、台帳へ記録する。
- 同じ活動を複数回申請・承認しても重複付与しない。
- Adminの操作履歴を残し、後から監査できる。
- 既存の貢献スコアとは独立した文明XPとして扱う。

**完了条件:** 申請者・承認者・付与量・理由を追跡でき、却下申請からXPが増えない。

### Phase 4 — 知識XPと理解度の確認

**目的:** 時間ではなく、実際に正解した知識の成果を文明に反映する。

- まずCampusSync内の採点可能な練習問題を対象にする。
- 問題ごとに難易度倍率を設定できるようにする。
- 初回正解を基本の付与対象とする。
- 同じ問題の繰り返し回答でXPを稼げないようにする。
- 正誤・回答者・問題ID・付与XPを保存する。
- 正誤判定のない自由記述や、単に開いただけの教材にはXPを付与しない。
- 小テストを対象にする場合は、解答データを安全に取得できることを確認してから接続する。

**完了条件:** 回答履歴からXPの根拠を説明でき、正解の再送信・連打・再挑戦で重複付与されない。

### Phase 5 — 惑星の文明発展エンジン

**目的:** XPと自然成長値を、惑星の状態・建物・技術の変化に結びつける。

- 学習XPで技術文明を発展させる。
- 学校貢献XPで社会文明を発展させる。
- 知識XPで研究・技術ツリーを解放する。
- CampusSync内の確認済みアクティビティ日数で自然環境を発展させる。
- 4つの成長軸を独立したレベルとして表示する。
- 各軸の条件を満たすと建物・景観・技術が解放される。
- 総合文明段階は定義済みの総合XPしきい値から決定する。
- ログインしない期間に惑星が衰退したり、過去に解放した施設が失われたりしない。
- 最初は少数の段階・建物から始め、追加しやすい定義データにする。

**完了条件:** テスト用XP・自然成長値を変えると、対応する成長軸だけが正しく進み、惑星の表示・解放施設が再計算結果と一致する。

### Phase 6 — 惑星詳細画面と惑星一覧

**目的:** 自分の惑星の進化を見て、将来は本人が公開を許可した惑星も発見できるようにする。

- CampusSync内に「惑星・文明」専用画面を追加する。
- 惑星のビジュアル、文明段階、各XP、各成長軸、解放履歴を表示する。
- 自分の惑星は常に表示する。
- 初期リリースでは他人の惑星一覧・公開検索を有効にしない。
- 後続版で公開機能を追加する場合は、本人の明示的な許可を必須とする。
- 公開プロフィールは惑星名・文明段階など許可された内容だけに限定し、学校メール・学籍番号・学習記録の詳細を表示しない。
- スマートフォンでも惑星全体と主要指標を快適に確認できるようにする。
- 既存Planetube統計画面は独立して維持する。

**完了条件:** 初期リリースでは本人以外が惑星を検索・参照できず、スマートフォンでも主要操作が完結する。

### Phase 7 — 共同ミッション・拡張

**目的:** 個人の惑星から、希望者が参加できる学校全体の体験へ広げる。

候補:

- 学校全体で協力して達成する共同ミッション
- 特定期間に公開される季節イベント
- 友人の惑星を訪問する機能
- 建物・自然環境・研究分野の追加
- 惑星の外観テーマ・名前・表示設定
- 学校全体の共同目標による特別な景観

初期リリースには含めない。個人の成長・XP・プライバシーが安定してから追加する。

**完了条件:** 参加・公開は任意で、個人の学習情報を必要以上に公開せずに共同イベントが成立する。

## 6. データ・セキュリティ・不正対策

- XP台帳は原則追記型とし、通常操作で履歴を直接削除・上書きしない。
- 誤付与の修正は、管理者による取消・調整履歴を別途記録する。
- 学習XPは学習記録ID、知識XPは問題IDとユーザーID、学校貢献XPは承認済み活動ID、自然成長値はユーザーIDと東京時間の日付を使って重複を防ぐ。
- クライアントで表示された数字を信用して直接加算しない。付与量はDBまたはサーバー側で再計算する。
- 生徒が任意のXP値を送って加算できるAPIを作らない。
- RLSを有効にし、別アカウントのXP台帳や非公開惑星を参照できないようにする。
- Admin権限は承認・監査など必要な処理に限定する。
- Planetube接続を成長計算に使わない。YouTube閲覧履歴・URL履歴・検索履歴・他アプリの利用状況を収集しない。
- 公開機能を将来追加する場合も、学校メール・学籍番号・学習記録の詳細を公開しない。
- 学習XPのために長時間勉強を競わせるランキングや、休んだことによる減点を作らない。
- 2つ以上のテストアカウントで、他人の惑星・台帳の参照や書き込みができないことを確認する。

## 7. テストとリリース基準

各フェーズで次を確認する。

### 機能テスト

- タイマーの開始・一時停止・再開・休憩切替・途中終了・記録保存
- XP計算の端数処理と東京時間の日次上限
- 同じ記録の再送信・二重クリック・再読み込み
- Admin承認・却下・差し戻し
- 練習問題の初回正解・誤答・再挑戦
- 自然成長値の対象日・同日複数アクティビティ・日付境界
- XPから文明レベル・施設が正しく導かれること
- 非公開設定で他アカウントから参照できないこと

### セキュリティテスト

- 生徒Aが生徒BのXP・惑星を取得できないこと
- 非公開惑星が一覧APIや直接URLから見られないこと
- 生徒が自分でXPを直接書き換えられないこと
- Admin以外が学校貢献XPを承認できないこと
- クライアントから任意の自然成長値を加算できないこと
- PlanetubeやYouTubeの履歴が取得・利用されていないこと

### リリース原則

GitHubへの変更、Supabase SQL適用、Cloudflareビルド・デプロイ、実ユーザーでの動作確認は別のチェックポイントとして扱う。SQLを追加しただけ、画面を作っただけ、ビルドが通っただけでは完了にしない。

## 8. 今回の実装順序と最初のゴール

最初から惑星一覧・全文明・共同ミッションまで一度に実装しない。

**最初のリリース目標はPhase 1〜2の安全な基盤と学習XPの一連の動作確認。**

1. XP台帳と個人惑星のデータ基盤を作る。
2. ポモドーロの集中記録から学習XPを一度だけ付与する。
3. CampusSyncに惑星・文明の基本画面を追加する。
4. 学習XPが増えると、惑星の技術発展と全体段階が進むところまで確認する。
5. 学習記録・XP付与・本人以外へのアクセス制限をテストする。

その後、学校貢献XP、知識XP、CampusSync内の自然成長、惑星の個別発展、公開機能の順に広げる。

これにより、最初の時点で「CampusSyncで学習する → XPを獲得する → 自分の惑星が成長する」という一連の体験を完成させ、その後に文明の奥行きを増やしていける。
