# CampusSync 惑星・文明システム ロードマップ

- 最終更新: 2026-11-20
- 対象: CampusSync 本体
- 状態: 設計確定案 / 実装前
- 実装ブランチ: `cloudflare-workers-migration`

この文書は、CampusSync内に個人の惑星を持ち、学習・学校への貢献・知識の習得・YouTubeを使わずに過ごせた時間に応じて、惑星の自然と文明が成長する仕組みを定義する。フェーズを順番に進め、既存のPlanetube機能や学校データを壊さず、小さく動作確認しながら拡張する。

---

## 1. プロジェクトの目的

CampusSyncの中に、生徒一人ひとりが自分の惑星と文明を持てる成長システムを作る。

学習記録を単なる時間や数字で終わらせず、積み重ねが惑星の見た目・施設・技術・社会の発展として見えるようにする。

### この機能の基本原則

1. **CampusSync内で完結させる。** XP、惑星、文明、建物、成長履歴はCampusSyncのSupabaseで管理する。
2. **Planetube本体は変更しない。** Planetubeの既存XP、惑星レベル、封印機能、ユーザーデータを書き換えない。
3. **既存のPlanetube統計画面を残す。** 現在のPlanetubeダッシュボードはPlanetubeの統計・実績を見る場所として維持する。文明画面に置き換えない。
4. **最初は一人につき一つのメイン惑星。** 複数惑星の所有・惑星間移住などは初期版の対象外。
5. **努力・理解・貢献を別々に評価する。** 勉強時間だけで知識が増えたことにせず、学校への貢献も学習時間と混ぜない。
6. **記録を消さず、不正な重複付与を防ぐ。** XPの根拠となる履歴を保存し、同じ活動からXPを二重に付与しない。
7. **競争を強制しない。** 学習時間の公開ランキングや、ログインしなかったことによる減点・惑星の衰退は作らない。

## 2. XPと惑星成長の全体設計

このシステムでは、3種類のXPと1種類の自然成長値を使う。名前が似ていても、用途を明確に分ける。

| 種類 | 何を評価するか | 主な獲得源 | 惑星で成長するもの |
|---|---|---|---|
| **学習XP** (Learning XP) | 学習に取り組んだ時間・努力 | CampusSyncのポモドーロ集中記録 | 科学技術、研究所、図書館、技術施設 |
| **学校貢献XP** (Contribution XP) | 学校や周囲への具体的な貢献 | 活動申請とAdmin承認 | 住宅、道路、公共施設、文化、都市 |
| **知識XP** (Knowledge XP) | 内容を理解し、正解などで知識を示した成果 | CampusSync内の練習問題・小テスト | 研究の解放、技術ツリー、専門分野 |
| **自然成長値** (Nature Growth) | YouTubeを使わずに過ごせた確認済みの時間 | Planetubeの完了済み封印セッション | 森林、海、生物多様性、生態系 |

### 2.1 学習XP — 技術文明を発展させる

- 初期案は、**集中時間1分につき1 XP**。
- ポモドーロの集中時間だけを対象とし、休憩時間は加算しない。
- 一時停止中の時間は加算しない。
- 途中終了でも、保存された有効な集中時間は対象にする。
- 学習記録を保存したタイミングで付与する。
- XPは消費する通貨ではなく、蓄積型の成長実績とする。
- 集中時間の記録自体はXPの上限を超えても保存する。XP付与上限を設ける場合も、学習記録を削ったり無効にしたりしない。

初期の調整案として、XP対象時間には1日あたりの上限を設定できるようにする。初期値候補は180分/日。これは学習を制限するものではなく、放置タイマー等による過剰なXP増加を抑えるためのXP計算上の上限であり、通常の学習時間記録は引き続き残す。実際の利用状況を見て正式値を決める。

**注意:** タイマーは集中セッションの記録であり、実際に内容を理解していたことまで証明するものではない。そのため、時間から付与するのは学習XPだけとし、知識XPは別の方法で判定する。

### 2.2 学校貢献XP — 社会・都市を発展させる

対象例:

- 委員会・生徒会・係の活動
- 学校行事の準備・運営
- 部活動での運営・支援・学校への貢献
- 学校環境の改善や、学校全体に役立つ活動
- Adminが認めたその他の具体的な貢献

付与の流れ:

1. 生徒が活動内容を申請する。
2. Adminが内容を確認する。
3. 承認された場合だけ学校貢献XPを付与する。
4. 承認者・理由・付与量・対象活動を履歴に残す。

単なる参加登録や自己申告だけでは付与しない。同じ活動の重複申請・重複承認を防ぐ。付与量はAdminが選ぶ定型値を基本とし、初期案は小規模10 XP / 通常25 XP / 大規模50 XP。実際の運用前にAdmin画面で調整可能にする。

現在の `contribution_scores` は日ごとのスコア管理、`contribution_history` は既存の貢献履歴として使われているため、新しい文明XPと同一視しない。既存テーブルの意味・参照箇所・RLSを監査してから、必要なら連携方法を決める。

### 2.3 知識XP — 研究・技術を解放する

知識XPは「勉強した時間」ではなく、**理解したことを確認できた成果**に付与する。

獲得候補:

- CampusSync内の練習問題に正解する。
- 公開された小テストに正解する。
- Admin・先生が登録した知識確認問題を解く。
- 初回挑戦・初回正解を重視し、同じ問題の繰り返しでXPを稼げないようにする。

初期案:

- 通常問題の初回正解: 2 XP
- 難易度の高い問題: Adminが設定した重みで増加
- 同じ問題の再正解: 学習履歴には残すが、原則として追加XPなし
- 正誤判定ができない課題・自由記述は、採点できる仕組みができるまで付与対象にしない

知識XPは学習XPの代用品ではない。タイマーを長く動かすだけでは知識XPは増えない。

### 2.4 自然成長値 — 惑星の自然環境を回復・発展させる

- Planetubeの封印セッション中にYouTubeを使わずに過ごせた、確認可能な時間を対象にする。
- 初期案は、**確認済みの封印時間30分につき自然成長値1**。
- セッション完了後に反映する。
- 同一の封印セッションIDから二重に自然成長値を付与しない。
- 自然成長値はXPとは別管理にする。

成長する要素:

- 草原・森林の拡大
- 海・水源の回復
- 植物や生物の種類
- 生態系の豊かさ
- 惑星の大気・自然環境の演出

**データ上の制約:** YouTubeの閲覧履歴やブラウザ全体の利用状況をCampusSyncが監視する設計にはしない。Planetubeから利用許可を得て取得できる、完了済み封印セッションの情報だけを使う。Planetube側で一時停止時間を除いた実時間を確認できない場合、その時間を推測で自然成長値に変換しない。必要なデータが確認できるまで、この成長軸は保留する。

## 3. 惑星・文明の構造

惑星は、4つの独立した成長軸を持つ。

| 成長軸 | 対応する値 | 見た目・機能の変化 |
|---|---|---|
| 技術文明 | 学習XP | 研究所、図書館、発電施設、交通技術、科学施設 |
| 社会文明 | 学校貢献XP | 住宅、道路、公園、公共施設、街並み、文化施設 |
| 研究・知識 | 知識XP | 技術ツリー、研究テーマ、専門施設、研究成果 |
| 自然環境 | 自然成長値 | 森林、海、動植物、大気、自然景観 |

### 3.1 文明段階

惑星の発展は、少しずつ見た目が変わる段階制にする。

初期段階案:

1. **原始惑星** — 自然が中心。文明施設はほぼない。
2. **集落時代** — 小さな住居・畑・簡素な道が現れる。
3. **都市形成期** — 住宅街、公共施設、研究所が増える。
4. **産業・研究時代** — 高度な施設、交通網、研究機関が発展する。
5. **高度文明** — 大都市、先端研究施設、豊かな文化・生態系が共存する。
6. **惑星文明** — 惑星全体に広がる高度な文明。さらに分野別の発展を継続できる。

段階の進行条件は、総XPだけで決めない。例えば技術だけが突出していても、社会文明や自然環境が極端に低ければ、全体が完成した文明にはならないようにする。各成長軸のレベルと、全体の文明段階を分けて表示する。

### 3.2 XPは消費させない

- XPを建物購入で消費する方式にはしない。
- 獲得したXPは累計値として残る。
- 一定の条件を満たすと施設・景観・技術が自動的に解放される。
- 解放済みの建物や環境は、ログインしない期間があっても失われない。
- XPの配分を後から変更して、過去の努力を不利益にしない。

### 3.3 文明の個性

学習XP・学校貢献XP・知識XP・自然成長値の比率によって、惑星ごとに異なる発展をする。

- 技術寄り: 研究施設や先端技術が発達した惑星
- 社会寄り: 都市・公共施設・文化が発展した惑星
- 研究寄り: 専門研究や知識施設が充実した惑星
- 自然寄り: 森林・海・生態系が豊かな惑星
- バランス型: 技術・社会・研究・自然が調和した惑星

特定の型が最強という仕組みにはしない。どの方向にも魅力や固有の建物・景観を用意する。

## 4. 画面・操作の設計

### 4.1 既存Planetube画面と新しい惑星画面を分離

CampusSync内に次の2つを設ける。

- **Planetube:** 現在のPlanetube統計・封印セッション・実績を確認する。既存の画面を維持する。
- **惑星・文明:** CampusSync独自のXP・惑星・文明・自然環境を確認する新しい画面。

Planetube画面を新しい文明画面に置き換えない。Planetube導入案内も、統計画面を邪魔しない補助リンクとして扱う。

### 4.2 惑星・文明のメイン画面

表示する内容:

- 惑星の大きなビジュアル
- 惑星名・文明段階・総合レベル
- 学習XP・学校貢献XP・知識XPの累計
- 技術文明・社会文明・研究・自然環境の各レベル
- 最近の成長履歴
- 次に解放される建物や技術
- 次の文明段階までの進捗

スマートフォンでも惑星の全体像とXP内訳を見られることを必須にする。小さな文字や横スクロールに依存しない。

### 4.3 惑星一覧・銀河マップ

惑星一覧では、生徒ごとの惑星をカードまたは銀河マップで表示する。

初期版:

- 自分の惑星を必ず表示する。
- 自分の惑星の詳細画面へ移動できる。
- 他人の惑星は公開許可がある場合だけ表示する。
- 公開する場合も、学校メール、学籍番号、学習記録の詳細、申請内容は表示しない。
- 公開は初期設定OFF。本人が明示的に許可した場合のみ公開する。

後続版:

- 公開惑星の検索・並び替え
- 文明段階や惑星の特徴による絞り込み
- 友人の惑星を訪問する表示
- 学校全体の共同ミッション

他人の惑星を見られることと、他人の個人データを見られることは明確に分離する。

## 5. 実装フェーズ

各フェーズは、完了条件を満たしてから次へ進む。複数フェーズを一度に実装して、データ不整合や原因不明の不具合を増やさない。

### Phase 0 — 仕様・画面設計の確定

**目的:** 実装前にXPの意味、獲得条件、画面構成を確定する。

- [x] CampusSync独自機能として作る。
- [x] Planetube本体のデータ・機能を変更しない。
- [x] 学習XP・学校貢献XP・知識XPを分離する。
- [x] 惑星の自然環境は確認済みの封印時間を根拠にする。
- [x] 既存Planetube統計画面を残し、文明画面を別にする。
- [x] 惑星は初期版では一人一つとする。
- [ ] XP付与量・上限・文明段階の必要値をテスト用データで最終調整する。
- [ ] スマートフォン・PCの画面ワイヤーフレームを確定する。

**完了条件:** XPの獲得条件、上限、段階条件、公開範囲が文書化され、実装時に判断がぶれない。

### Phase 1 — データベースとXP台帳の基盤

**目的:** XPを安全に保存し、あとから正確に再計算できる仕組みを作る。

設計する主なテーブル:

| テーブル案 | 役割 |
|---|---|
| `campus_planets` | ユーザーごとの惑星名・公開設定・作成日時 |
| `campus_xp_ledger` | XPの付与履歴。種別・量・理由・発生元を保存 |
| `campus_planet_growth` | 技術・社会・研究・自然の成長値とレベル |
| `campus_planet_unlocks` | 解放済み建物・技術・景観 |
| `campus_planet_events` | 文明段階アップなどのイベント履歴 |

実装要件:

- XPの台帳を唯一の正本とし、累計値は台帳から再計算できるようにする。
- 同じ発生元ID・XP種別の二重付与をDB制約で防ぐ。
- XP付与はサーバー側の検証済み処理を通す。クライアントから自由にXPを書き込めないようにする。
- XP付与と惑星成長値の更新は、可能な限り一つのトランザクションで行う。
- 生徒は自分の惑星・自分の台帳だけを参照できるRLSにする。
- Admin権限は必要な承認・監査処理だけに限定する。
- 既存の貢献スコア・学習履歴テーブルを変更する場合は、先に依存箇所を調査する。

**完了条件:** 2つ以上のテストアカウントで、他人のXP・惑星を読み書きできない。重複登録・連続送信・再読み込みでもXPが二重に増えない。

### Phase 2 — ポモドーロと学習XPの連携

**目的:** 最初の実際に動くXP獲得経路を作る。

- CampusSyncの集中モードで保存した学習記録を対象にする。
- 有効な集中秒数から学習XPを計算する。
- 休憩秒数・一時停止時間は除外する。
- 途中終了した場合も、保存された有効な集中時間を対象にする。
- 学習記録ID単位でXP付与済みかを管理する。
- 付与したXPと根拠となる学習記録を確認できるようにする。
- XPの対象上限を設けても、通常の学習時間・履歴は削除しない。

**完了条件:** タイマーを開始・一時停止・再開・途中終了・完了した全パターンで、集中時間とXPが一致する。更新・再送信による二重付与が発生しない。

### Phase 3 — 学校貢献XPとAdmin承認

**目的:** 学校への貢献を適切に評価し、社会文明に反映する。

- 生徒が活動内容・実施日・説明を申請できる。
- Adminに承認待ち一覧を設ける。
- 承認・却下・差し戻しの状態を管理する。
- 承認時にXP量と理由を確定し、台帳へ記録する。
- 同じ活動を複数回申請・承認しても重複付与しない。
- Adminの操作履歴を残し、後から監査できる。
- 既存の貢献スコアとは独立した文明XPとして扱う。

**完了条件:** 申請者・承認者・付与量・理由を追跡でき、却下申請からXPが増えない。

### Phase 4 — 知識XPと理解度の確認

**目的:** 時間ではなく、実際に正解した知識の成果を文明に反映する。

- まずCampusSync内の採点可能な練習問題を対象にする。
- 問題ごとにXP重みを設定できるようにする。
- 初回正解を基本の付与対象とする。
- 同じ問題の繰り返し回答でXPを稼げないようにする。
- 正誤・回答者・問題ID・付与XPを保存する。
- 正誤判定のない自由記述や、単に開いただけの教材にはXPを付与しない。
- 小テストを対象にする場合は、解答データを安全に取得できることを確認してから接続する。

**完了条件:** 回答履歴からXPの根拠を説明でき、正解の再送信・連打・再挑戦で重複付与されない。

### Phase 5 — 惑星の文明発展エンジン

**目的:** XPと自然成長値を、惑星の状態・建物・技術の変化に結びつける。

- 学習XPで技術文明を発展させる。
- 学校貢献XPで社会文明を発展させる。
- 知識XPで研究・技術ツリーを解放する。
- 確認済みのPlanetube封印時間で自然環境を発展させる。
- 4つの成長軸を独立したレベルとして表示する。
- 各軸の条件を満たすと建物・景観・技術が解放される。
- 複数軸のバランスに応じて惑星全体の文明段階を決定する。
- ログインしない期間に惑星が衰退したり、過去に解放した施設が失われたりしない。
- 最初は少数の段階・建物から始め、追加しやすい定義データにする。

**完了条件:** テスト用XPを変えると、対応する成長軸だけが正しく進み、惑星の表示・解放施設が再計算結果と一致する。

### Phase 6 — 惑星詳細画面と惑星一覧

**目的:** 自分の惑星の進化を見て、他の公開惑星も発見できるようにする。

- CampusSync内に「惑星・文明」専用画面を追加する。
- 惑星のビジュアル、文明段階、各XP、各成長軸、解放履歴を表示する。
- 惑星一覧・銀河マップを追加する。
- 自分の惑星は常に表示する。
- 他人の惑星は本人が公開を許可したものだけ表示する。
- 公開プロフィールは惑星名・文明段階・公開設定で許可された内容だけに限定する。
- スマートフォンでも惑星全体と主要指標を快適に確認できるようにする。
- 既存のPlanetube統計画面は独立して維持する。

**完了条件:** 公開OFFの惑星は他の生徒から一切検索・参照できず、スマートフォンでも主要操作が完結する。

### Phase 7 — 共同ミッション・拡張

**目的:** 個人の惑星から、希望者が参加できる学校全体の体験へ広げる。

候補:

- 学校全体で協力して達成する共同ミッション
- 特定期間に公開される季節イベント
- 友人の惑星を訪問する機能
- 建物・自然環境・研究分野の追加
- 惑星の外観テーマ・名前・表示設定
- 学校全体の共同目標による特別な景観

初期リリースには含めない。個人の成長・XP・プライバシーが安定してから追加する。

**完了条件:** 参加・公開は任意で、個人の学習情報を必要以上に公開せずに共同イベントが成立する。

## 6. データ・セキュリティ・不正対策

- XP台帳は原則追記型とし、通常操作で履歴を直接削除・上書きしない。
- 誤付与の修正は、管理者による取消・調整履歴を別途記録する。
- 学習XPは学習記録ID、知識XPは回答・問題ID、学校貢献XPは承認済み活動ID、自然成長値はPlanetube封印セッションIDで重複を防ぐ。
- クライアントで表示された数字を信用して直接加算しない。付与量はDBまたはサーバー側で再計算する。
- 生徒が任意のXP値を送って加算できるAPIを作らない。
- RLSを有効にし、別アカウントのXP台帳や非公開惑星を参照できないようにする。
- Planetube接続は本人確認・明確な同意の下で必要最小限の読み取りだけを行う。
- YouTube閲覧履歴・URL履歴・検索履歴を収集しない。
- 公開惑星に学校メール・学籍番号・学習記録の詳細を載せない。
- 学習XPのために長時間勉強を競わせるランキングや、休んだことによる減点を作らない。

## 7. テストとリリース基準

各フェーズで次を確認する。

### 機能テスト

- タイマーの開始・一時停止・再開・休憩切替・途中終了・記録保存
- XP計算の端数処理と上限
- 同じ記録の再送信・二重クリック・再読み込み
- Admin承認・却下・差し戻し
- 練習問題の初回正解・誤答・再挑戦
- Planetube封印セッションの完了・一時停止・キャンセル・重複
- XPから文明レベル・施設が正しく導かれること
- 非公開・公開設定の切り替え

### セキュリティテスト

- 生徒Aが生徒BのXP・惑星を取得できないこと
- 非公開惑星が一覧APIや直接URLから見られないこと
- 生徒が自分でXPを直接書き換えられないこと
- Admin以外が学校貢献XPを承認できないこと
- Planetube連携が本人以外のセッションを取得しないこと

### リリース原則

GitHubへの変更、Supabase SQL適用、Cloudflareビルド・デプロイ、実ユーザーでの動作確認は別のチェックポイントとして扱う。SQLを追加しただけ、画面を作っただけ、ビルドが通っただけでは完了にしない。

## 8. 今回の実装順序と最初のゴール

最初から惑星一覧・全文明・共同ミッションまで一度に実装しない。

**最初のリリース目標は Phase 1〜2。**

1. XP台帳と個人惑星のデータ基盤を作る。
2. ポモドーロの集中記録から学習XPを一度だけ付与する。
3. CampusSyncに惑星・文明の基本画面を追加する。
4. 学習XPが増えると、惑星の技術発展が一段階進むところまで確認する。

その後、学校貢献XP、知識XP、自然成長、惑星一覧の順に広げる。

これにより、最初の時点で「タイマーで勉強する → XPを獲得する → 自分の惑星が成長する」という一連の体験を完成させ、その後に文明の奥行きを増やしていける。
