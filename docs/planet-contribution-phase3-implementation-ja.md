# CampusSync Phase 3 — 学校貢献XPとAdmin承認

## 対象範囲

Phase 3は、CampusSync内で行った学校への貢献活動を生徒が申請し、Adminが内容を確認・承認した場合だけ、CampusSync独自の学校貢献XPを惑星へ加算する機能です。

既存の contribution_scores、contribution_history、貢献度の剣ランクは変更しません。過去の既存ポイントを新しいXPへ移行・変換することもありません。

## 生徒の操作

- 活動名（3〜120文字）、活動日、活動内容（10〜2000文字）を入力して申請する。
- 自分の申請状態と審査履歴だけを確認できる。
- 審査待ちの申請は取り下げられる。
- 差し戻された申請は内容を修正して再提出できる。
- 承認済みの申請は付与されたXP量と審査コメントを確認できる。

## Adminの操作

- 申請一覧から生徒名・クラス・活動内容を確認する。
- 承認時は固定値10 / 25 / 50 XPから選択する。
- 却下・差し戻しには5〜500文字の理由を必須にする。
- 申請・再提出・取り下げ・審査結果を追記型イベントとして記録する。
- Admin APIは既存のCAMPUS_SYNC_ADMIN_PASSWORDによる認証済みセッション／パスワードヘッダーを使用する。

## 初期XP

| 区分 | XP |
|---|---:|
| 小規模な貢献 | 10 |
| 通常の貢献 | 25 |
| 大きな貢献 | 50 |

## DB・セキュリティ

- campus_contribution_submissions: 申請内容と現在の審査状態。
- campus_contribution_review_events: 申請・審査の監査履歴。
- 両テーブルにRLSを設定し、生徒は本人分だけSELECTできる。生徒の直接書き込み権限は付与しない。
- 作成・更新・審査・XP付与はサーバーからservice_role限定RPCを呼び出す。
- 承認RPCは申請行をFOR UPDATEでロックし、承認状態、XP台帳、監査履歴、惑星成長再計算を同一トランザクションで処理する。
- campus_xp_ledgerの既存一意制約と申請状態検査で二重付与を防ぐ。
- Adminは共有パスワードで認証されるため、審査者表示は個人名ではなくCampusSync Adminとする。

## 検証項目

- 入力バリデーション（文字数、実在日付、UUID、固定XP値）。
- 生徒A/Bで申請・履歴の相互参照ができないこと。
- 生徒トークンで直接INSERT/UPDATE/DELETEができないこと。
- Admin以外は審査APIを実行できないこと。
- 却下・差し戻しに理由が必須であること。
- 同じ申請の並行承認・再送信でXPが重複しないこと。
- 承認とXP付与が失敗時に部分反映されないこと。
- 既存ポイント・剣ランク・学習XP・知識XP・Planetube・時間割・課題・LINE送信に変更がないこと。
